### 🟡 中等问题（建议修复）

**P2. 嗜血者人数上限约束不一致**
- **位置**：
  - `1.2.2` 行 113：`上限 ⌊n/3⌋`
  - `1.5.1 RC1` 行 365：`1 ≤ k(BLOODTHIRSTY) ≤ ⌊n/3⌋`
  - `4.1 INV6` 行 1244：`1 ≤ |{p ∈ P | R(p) = BLOODTHIRSTY}| ≤ ⌊n/3⌋`
- **问题**：用户要求的约束是"不得大于总人数的 **1/5**"（见用户反馈第7条）
- **当前实现**：文档使用 `⌊n/3⌋`（约 33.3%）
- **用户要求**：`≤ ⌊n/5⌋`（20%）
- **影响**：核心游戏平衡参数与用户需求不符
- **建议**：全局替换为 `⌊n/5⌋`，同步修改：
  - `1.2.2` 行 113
  - `1.5.1 RC1` 行 365
  - `4.1 INV6` 行 1244
  - `1.5.4` 示例部分的计算结果

**P3. 普通人占比约束缺失**
- **位置**：`1.5.1` 初始化配置部分
- **问题**：用户要求"普通人占比应大于总人数的 1/4 但不超过 3/5"（见用户反馈第4条）
- **当前实现**：普通人数量完全由外部 `k_civilian` 决定，引擎不校验占比
- **影响**：可能出现普通人过少或过多的不合理配置
- **建议**：
  - **选项 A（推荐）**：在 `1.5.1` 的 `VALID(k, n)` 中增加 **RC6 约束**：
    ```
    RC6. 普通人占比约束：
    n/4 < k(CIVILIAN) ≤ 3n/5
    即普通人数量必须严格大于总人数的 1/4（开区间），不超过 3/5
    ```
  - **选项 B**：若坚持引擎最小接口，则在文档中明确说明"普通人占比由调用方负责校验"

**P4. 信息报告约束的实现歧义**
- **位置**：`3.2.3` 辩论时，行 985-999
- **问题**：
  - 文档要求"必须先公开身份"（行 986-990）
  - 但同时说明"公开的身份可以是谎报的"（行 997）
  - "GM 不验证公开身份的真实性"（行 999）
- **歧义**：如果 GM 不验证，那么"公开身份"这个步骤的技术含义是什么？
  - 是仅仅标记 `revealed(p) = REVEALED`？
  - 还是玩家声称一个身份后，系统记录这个声称？
- **影响**：实现层不清楚如何处理"谎报身份+公开"的流程
- **建议**：
  - 在 `3.2.3` 明确说明：
    ```
    玩家执行"公开身份"时：
    1. 玩家声明："我是 [角色名]"（可以是谎报）
    2. GM 将该玩家的 revealed 状态置为 REVEALED
    3. GM 记录该玩家声称的身份（claim_identity）
    4. 其他玩家只能看到：
       - 该玩家已公开身份（revealed = true）
       - 该玩家声称的身份（claim_identity）
       - 但不知道真实身份（R(p)）
    ```

**P5. 大法师复活的治安角色技能限制不完整**
- **位置**：`2.4.1` 行 795
- **问题**：
  - 文档说"复活的治安角色不能在本轮再次使用技能"
  - 但没有明确"下一轮"能否使用
  - 没有明确复活后的冷却时间状态
- **影响**：极端场景下行为不确定（如复活的大法师冷却时间如何处理？）
- **建议**：
  - 补充说明：
    ```
    复活的治安角色限制：
    - 本轮（复活当轮）不能使用技能
    - 下一轮起恢复正常技能使用权
    - 若复活的是大法师，其冷却时间状态保持不变（死亡前的冷却继续）
    - 若复活的是圣骑士/圣杀者，下一轮可正常使用技能（若未曾使用过则 revealed 仍为 HIDDEN）
    ```

## 🎯 关键设计决策审查

### ✅ 合理的设计

1. **引擎最小接口原则**
   - 决策：引擎只暴露 `role_pool_flags`，不提供人数推导
   - 评价：**优秀**。保持引擎通用性，策略灵活性交给外部
   - 理由：符合职责分离原则，便于测试和配置

2. **超限均匀随机抽取**
   - 决策：唯一身份超限时随机抽取，不引入优先级
   - 评价：**合理**。避免硬编码策略，保证公平性
   - 理由：优先级是游戏设计决策，不应固化在引擎中

3. **术语统一**
   - 决策：明确区分 Identity(身份) / player_id / seat_id
   - 评价：**非常必要**。消除了原文档的最大歧义源
   - 理由：原文档"身份"一词五种用法导致理解困难

### ⚠️ 需要讨论的设计

1. **普通人占比校验的缺失**（见 P3）
   - 决策：完全不校验普通人占比
   - 风险：可能出现不合理配置（如普通人占比 90% 或 5%）
   - 建议：至少添加警告或文档说明

2. **信息报告的"假公开"机制**（见 P4）
   - 决策：允许玩家谎报身份后公开
   - 疑问：这个机制是否符合游戏设计初衷？
   - 建议：需要用户确认这是期望的玩法
